# Research roadmap

Unchecked items are not implemented or verified. Move stable findings to their
owning document as work lands; remove superseded items.

- [ ] Review CPU92→CPU95 rate pairs against full disclosures, including copy
      counts, OS, compiler, tuning and architecture-specific held-out errors.
- [ ] Review hardware-near CPU95→CPU2026 rate pairs against detailed disclosures;
      especially check copy counts, software, memory and enabled hardware.
- [ ] Refit the CPU2026 edge as its published integer-rate cohort grows, and
      seek independent nonadjacent or three-suite overlaps for a cycle check.
- [ ] Quantify the uncertainty of the full CPU92→CPU2026 rate chain before
      treating its VAXen figures as an annual performance index.
- [ ] Build an annual **rate-only** machine timeline using source-checked
      hardware availability dates and the current fit, keeping base/peak and
      reported/estimated scores separate.
- [ ] Search original early SPEC newsletters for additional CPU92 rate
      disclosures, especially before the 1993 Netlib coverage; keep the 1992
      Digital manufacturer brief separate from official submissions.
- [ ] When historical PDF and KIPS extraction begins, choose a script-readable
      format and schema for checked values and related observations, define
      stable source/result IDs and migrate checked numeric examples.
- [ ] Evaluate MinerU or another OCR tool on representative historical scans;
      verify page mapping and table transcription before using values.
- [ ] Inspect shortlisted bitsavers PDFs for model-specific timings and cite
      page numbers; reproduce published instruction-mix capacity examples.
- [ ] Work through the [machine watchlist](machine-watchlist.md), including
      original LINC timing and Honeywell 6180 hardware revisions.
- [ ] Assess CoreMark public score coverage, certification and concurrency,
      then seek same-system overlaps only if its rate convention is comparable.
