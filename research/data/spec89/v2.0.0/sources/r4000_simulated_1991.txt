I realize that the following is somewhat borderline.  It is my hope that by
providing a full disclosure rather than a single number, that you are able
to understand some of the variables that have left MIPS uneasy about SPEC's
approval of publication of simulated results.  We have attempted to
document all of our assumptions that were made in the simulations.

The following R4000 results are based on simulations using the R4000 cache
simulator.  These numbers remain as preliminary estimated values until the
benchmarks are run on an R4000-based system.  The SPEC benchmarks suite,
release 1.2b is used for this analysis.  The numbers will be updated as new
revisions of the simulation model are available.

Simulations were done with a compiler under development (pre-alpha 3.10).
The compiler options used were -mips2, -Gnum and -O3.  Other options used
in some of the programs are:

	020.nasa7:	-ddopt -inline_to 1 -nonIEEEfp
	013.spice2g6:	-noinline
	047.tomcatv:	-ddopt -nonIEEEfp
	030.matrix300:	-ddopt -inline_to 3
	023.eqntott:	-Wb, -xbb
	042.fpppp:	-O2

Using the same simulation methodology, the R3000 simulation data is
approximately 3%-5% conservative compared to results from the actual
machine.  However, until the Cache4000 model is compared to actual silicon,
it is unknown whether these results are accurate.

The SPEC benchmark suite has I/O routine calls that cannot be simulated
accurately on the cache simulator, especially for GCC.  I/O time estimates
extracted from RC6260 systems are added to the simulated user time to
arrive at a more accurate total time.

The following sections tabulate 4 sets of results for 4 different processor
configurations:

	1) R4000SC model1 (50 MHz R4000 with 4MB secondary Cache)
	2) R4000PC model1 (50 MHz R4000 with primary cache only)
	3) R4000SC model2 (50 MHz R4000 with 1 MB secondary Cache)
	4) R4000PC model2 (50 MHz R4000 with primary cache, different
	   refill model)

The original of this report was done by I. Lui in the Technology
Performance Group Marketing organization, based on extensive simulations
done by MIPS Engineering.

Note that all of this data is based on MIPS products only.  MIPS did not
use any outside pre-processors for compilation.

MIPS has chosen to use a Geometric Mean of 60 as a conservatively rounded
figure for R4000 processors with Secondary Cache.

MIPS has chosen to use a Geometric Mean of 40 as a conservatively rounded
figure for R4000 processors with only Primary Cache.
Simulated SPEC Results (** Not official SPEC Results)

R4000SC model1(50MHz R4000 with secondary cache):

8KB of primary instruction cache, 8KB of primary data cache,
	4 word refill for primary instruction cache,
	4 word refill for secondary instruction cache,
4MB secondary cache configured as joint instruction and data caches,
	16 word refill for secondary cache,
	15ns secondary cache SRAMs (minimum seondary cache access time)
Assume main memory is large enough that there are no paging effects (e.g.,
main memory > 16 MB)
	180ns main memory latency to the first word,
	2 doublewords (128 bits) per 60ns as the memory data pattern
	40ns DRAM precharge time
